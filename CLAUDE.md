The site is intended to:
- present my background professionally

## Design Direction

The site is a walk through an illustrated park, in a soft
storybook / Ghibli-inspired style. Each section is a spot in the park
(entrance, old oak, notice board, trail, courts & tables, garden, far
gate), and the sky moves from morning to dusk as the visitor walks.
The dark theme is the same park at night.

On large screens the park is walked sideways (scrolling slides the
sections horizontally; see `app/components/park/ParkWalk.tsx`). On
phones, tablets in portrait, and with reduced motion, sections stack
vertically.

The overall feeling should be:

- warm
- calm
- playful but not childish
- polished
- recruiter-friendly: content stays readable and easy to skim

Illustrations are hand-written inline SVG built from the pieces in
`app/components/park/`. Keep text on paper cards or plain sky, never
over busy illustration.

---

## Color Palette

All colors are tokens in `app/globals.css` (day in `:root`, night in
`[data-theme="dark"]`): soft greens, warm wood and paper, pastel skies.

Avoid:
- large areas of pure black or pure white
- neon or highly saturated colors
- rainbow gradients
- excessive glassmorphism

Keep text contrast at 4.5:1 or better on paper and on every sky.

---

## Typography

Use system fonts: the sans stack for body text and a bookish system
serif (`font-display`) for headings.

Prefer:

- large, confident hero typography
- clear heading hierarchy
- comfortable body text
- restrained use of font weights
- generous line-height
- strong readability

Avoid excessive font sizes and decorative fonts.

---

## Layout

Use:

- generous whitespace
- strong vertical rhythm
- centered content containers
- responsive layouts
- large editorial sections
- clean alignment

Prefer a few strong elements per section rather than many small cards.

The site should feel spacious rather than dense.

Navigation should be:

## Hero Section

The hero should prioritize:

1. My name
2. My professional/academic headline

## Project Section

Projects should be the most important portfolio content.

Project components should support:

- title
- description
- technologies
- GitHub link
- optional live demo
- optional image
- optional longer project page in the future

Do not invent projects.

Keep project cards visually polished but restrained.

Prefer:
- soft surfaces
- subtle borders
- rounded corners
- gentle hover behavior

Avoid:
- huge shadows
- excessive animation
- cluttered technology badges

---

## Motion

Animations should be subtle.

Preferred:
- opacity transitions
- small translate transitions
- gentle hover effects
- approximately 200–400ms durations

Respect `prefers-reduced-motion`.

Do not add:
- excessive parallax
- animated cursors
- distracting background animations
- unnecessary page loaders
- constant movement

## Coding Style

Use TypeScript.

Prefer:
- simple components
- meaningful names
- reusable components
- clear props
- readable code
- straightforward solutions

Avoid:
- premature abstraction
- giant components
- unnecessary state
- unnecessary client components
- unnecessary dependencies
- overly clever code

Use Server Components by default when possible.

Only use `"use client"` when client-side behavior actually requires it.

---

## Editing Rules

Before making a large change:

1. inspect the relevant existing files
2. understand the current implementation
3. preserve functionality that is unrelated to the request
4. make the smallest reasonable set of changes

Do not rewrite unrelated sections of the site unless necessary.

For major redesigns, explain the plan before implementing it.
